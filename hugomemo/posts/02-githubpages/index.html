2. GitHub Pages の作り方

GitHub Pages はいわゆる無料ホームページサービスである。 ただし CGI や PHP などサーバーサイドプログラミング環境は使えず、 静的 HTML と JavaScript だけで構築する必要がある。

GutHub Pages の作成方法

  1. GitHub に「ユーザー名.github.io」というリポジトリを作ると自動的に GitHub Pages になる。 ユーザー名が yuimax なら、リポジトリ名は yuimax.github.io である。
  2. リポジトリの作成手順は他の git プロジェクトと同じである。
    まずローカルに yuimax.github.io フォルダを作り、そこに移動する。 
    mkdir yuimax.github.io
cd yuimax.github.io
  3. フォルダに .gitignore を作っておく。下記は当サイトの実例。 
    .*
_*
    .env 等をうっかり公開しないよう、ピリオドネームはデフォルトで管理対象から除外する。
  4. README.md も作っておく。当サイトの実例。 
    # yuimax.github.io
* https://yuimax.github.io
  5. ここが Web サイトのルートになるので index.html も作っておく。当サイトの実例。 
    <!DOCTYPE html>
<html lang="ja">
<head><meta charset="utf-8"></head>
<body><p>ここをキャンプ地とする</p></body>
</html>
  6. フォルダをローカルリポジトリ化し、GitHub に push する。 
    git init
git add .
git commit -m "initial commit"
gh repo create --source=. --public --push
  7. GitHub のリポジトリを確認する。
    ＞ https://github.com/yuimax/yuimax.github.io
  8. しばらく待つと https://リポジトリ名/ でブラウザからアクセス可能になる。
    ＞ https://yuimax.github.io/

独自ドメインのサブドメインでアクセスする

自分の管理するドメインを GitHub Pages に割り当てることができる。 ルートドメインの割り当ても可能だが、ここではサブドメインを使う方法を書く。 参考＞ GitHub Pages: サブドメインを設定する

DNSの設定： doc.yuimax.org → yuimax.github.io

  1. まず自ドメインのゾーン設定に次の CNAME レコードを追加する。 
    doc.yuimax.org. IN  CNAME  yuimax.github.io.
  2. ただしドメインの設定方法は管理ツールによりいろいろである。
    うちで使っている「さくらのドメイン」の場合、管理画面で下記を設定すればよい。 
    エントリー名	タイプ	データ
doc             CNAME   yuimax.github.io.
    user-name.github.io. の最後にピリオド . が必須 なので注意。

GitHub の設定： doc.yuimax.org 経由のアクセスを有効にする

  1. ブラウザで GitHub Pages のリポジトリを開き、Settings 画面を開く。
    ＞ https://github.com/yuimax/yuimax.github.io/settings
  2. 左のサイドバーから Pages メニューを選択する。
    ＞ https://github.com/yuimax/yuimax.github.io/settings/pages
  3. 下のほうに Custom domain という入力欄があるので、 
    doc.yuimax.org
    と入力して、[Save] ボタンを押す。

設定の確認

  1. しばらく(2～3分)待つと自ドメインが有効になるので、新しい URL でアクセスしてみる。
    ＞ https://doc.yuimax.org/
    ブラウザのアドレスバーに doc.yuimax.org の URL が表示されれば成功である。
  2. リポジトリには CNAME というファイルが作られている。
    ＞ https://github.com/yuimax/yuimax.github.io
  3. 元の URL でもアクセスできるが、新しい URL に飛ばされてしまう。
    ＞ https://yuimax.github.io/
    アドレスバーを見ると doc.yuimax.org にリダイレクトされたことがわかる。

GitHub 側の変更をローカルリポジトリに反映する

  1. GitHub 側で CNAME というファイルが追加されたので、ローカルリポジトリにも反映しておく。 
    git pull

GitHub Pages では自動的に Actions が起動する

  1. 普通のリポジトリを GitHub に push しただけでは何も起きない。
    デフォルトでは Actions が登録されていないからである。
    例： https://github.com/yuimax/myproject/actions
  2. しかし GitHub Pages の場合は、自動的にサイト構築用の Actions が登録される。
    例： https://github.com/yuimax/yuimax.github.io/actions
    GitHub Pages のリポジトリを push すると、この Actions が起動する。
  3. 上記のページで最新ログの行をクリックすると、実際におこなった処理が表示される。
    この GitHub Pages の Actions では、
    | build
    | report-build-status
    | deploy
    という3つのジョブが実行されていることがわかる。

GitHub Actions の進行を監視する

  1. Actions の進行は gh コマンドで監視できる。 これを利用して、GitHub Pages の生成完了を待つ PowerShell スクリプトを作ってみる。
  2. PowerShell は古い powershell.exe ではなく、v7版の pwsh.exe を使用する。
    まだ入れてなければインストールする。 
    winget install --id Microsoft.PowerShell --source winget
  3. pwsh.exe の動作確認。 
    pwsh --version
  4. ローカルリポジトリに、次のファイルを deploy.ps1 という名前で保存する。 ファイルの文字コードは UTF-8 とする。 
    # 現在の日時を取得
$timestamp = Get-Date -Format "yyyy/MM/dd HH:mm (UTCz)"

# ローカルリポジトリの変更をコミットしてプッシュ
git add .
git commit -m "cmt: $timestamp"
git push origin main

# GitHubの準備ができるまで少し待つ
Start-Sleep -Seconds 3

# 最新の実行IDを取得
$id = gh run list --limit 1 --json databaseId --jq '.[0].databaseId'
if (!$id) {
    Write-Host "`n実行中の Actions がありません。"
    exit
}

# 実行IDを監視
gh run watch $id

# 終了メッセージを表示する
$result = gh run view $id --json conclusion --jq '.conclusion'
if ($result -eq "success") {
    Write-Host "`nActions が完了しました。";
} else {
    Write-Host "`n処理が失敗しました (Result: $result)"
}
    ここでは gh run list ... で実行中の Actions の ID を取得し、 gh run watch $id で進行を監視している。
  5. ローカルリポジトリを変更したら、いつもの add→commit→push の代わりに、 このスクリプトを pwsh.exe で実行する。 
    pwsh deploy.ps1
    すると Actions の進行状況がリアルタイムに表示される。
    最後に「Actions が完了しました。」が出れば GitHub Pages の更新は完了である。
    ＞ https://github.com/yuimax/yuimax.github.io
    これでもうページをリロードしつつ、更新まだかな～と待つ必要はない。
