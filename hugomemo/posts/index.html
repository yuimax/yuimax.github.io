3. Hugo で作る GitHub Pages

Hugo は静的 Web サイト構築ツールである。
ここでは Windows で Hugo を利用し、GitHub Pages を作る手順を示す。

Hugo と GitHub Pages の関係

Hugo で GitHub Pages を作る方法は2つある。

  • ローカルの Hugo で HTML ページを作る → GitHub に push する。
  • GitHub に Markdown を push → サーバー側の Hugo がページを更新。

今回はローカルの Hugo で作った HTML ページを push する方法にした。
そのほうが手元で校正しやすいので。

ツールのインストール

  1. Hugo をインストールする。winget を使うと簡単である。 
    winget install Hugo.Hugo.Extended

プロジェクトの作成

  1. ひとつのサイトごとに Hugo のプロジェクトを作成する。
    ここでは hugomemo というプロジェクト名にしてみた。
    無事にプロジェクトが完成すると、フォルダが作られているので、そこに移動する。 
    hugo new site hugomemo
cd hugomemo
  2. 設定ファイルの準備。
    プロジェクトのルートにある hugo.toml という設定ファイルを編集する。 
    # hugo.toml を修正
baseURL = "https://example.net/hugomemo/"
title = "Hugo memo"
ignoreFiles = ["/__"]
    baseURL はルート以下のフォルダ構成を示すもので、実際のドメイン名を指定する必要はない。
    title はデフォルトで全大文字表示されるが、後で CSS の設定で通常表示に戻す。
    ignoreFiles で除外ファイルを指定する。ここではアンダーバー2個で始まる名前を除外。

テーマの設定

  1. 画面テーマをインストールする。
    git init でプロジェクトをリポジトリ化し、git submodule でテーマを入れる。
    今回は Mainroad というテーマを選んだ。サイドバーが作りやすいらしい。 
    git init
git submodule add https://github.com/vimux/mainroad.git themes/mainroad
  2. 設定ファイルでテーマを設定する。
    hugo.toml に、次のようにテーマ名と言語設定を追加。 
    # hugo.toml に追加
theme = "mainroad"
locale = "ja-jp"
defaultContentLanguage = "ja"
  3. サイドバー関連も設定する。
    hugo.toml に、次のようにサイドバー関係の設定を追加。 
    # hugo.toml に追加
[params.sidebar]
home = "left"        # トップページのサイドバー位置
single = "left"      # 個別記事ページのサイドバー位置
widgets = ["recent"] # サイドバーに 「最近の投稿」を表示する

[params.widgets]
recent_num = 20      # 「最近の投稿」に表示する件数

トップページの設定

  1. ファイル layouts/index.html を作り、トップページのテンプレートを設定する。 
    {{ define "main" }}
  <!-- _index.md の本文のみを表示 -->
  <div class="content">
	{{ .Content }}
  </div>
{{ end }}
  2. ファイル content/_index.md を作り、トップページの内容を設定する。
    ファイル名にアンダーバーを付けて _index.md とすることに注意。 
    # Hugo memo トップページ
Hugo の使い方に関する備忘メモ。

記事の作成

  1. 個別記事のフォルダ構成について。
    content/posts の下に記事フォルダを作り、その中の index.md に記事内容を書く。
    この記事のみで使う画像などがあれば記事フォルダに入れる。 
    content
|
+-- _index.md  <-- トップページのソース
|
+-- posts
	|
	+-- 01-firstpost  <-- 記事ごとにフォルダを作る
	|   |
	|   +-- index.md  <-- 記事のソースを書く
	|   |
	|   +-- img1.png  <-- この記事のみが参照する画像
	|
  2. 記事のソース (index.md) は、フロントマター（ヘッダ部分）と記事本体で構成される。
    実際の index.md の例を下記に示す。 
    +++
title = "0. 投稿のテスト"
date  = 2026-10-01T09:00:00+09:00
draft = false
+++

* これはテストです。
* **太字** も使えます。

![ALT](img01.jpg)
![ALT](img02.jpg)
  3. フロントマターについて。
    YAML/TOML/JSON 形式が利用できる。本サイトでは TOML を使う。
    TOML 形式は上下を +++ で囲む。

    フロントマターのおもな項目：
    title = "記事タイトル"
    description = HTML の <meta name="description" ...> になる
    draft = 下書き段階なら true、公開時は false にする
    tags = このページのタグ、例: tags=["tagA", "tagB"]
    categories = カテゴリ、例: categories=["cateA", "cateB"]
    weight = 記事の並び順（値が小さい順、マイナス値も可）
    date = 公開日時（ISO 8601形式）、weight が同じ場合は date の新しい順に並ぶ
  4. 記事本文について。
    本文は Markdown で書く。Markdown にもいろいろ方言があるが、
    CommonMark と GitHub Flavored Markdown に対応しているらしい。

CSS をカスタマイズし、独自のスタイルを指定する

  1. hugo.toml に次の設定を追加する。 
    # hugo.toml に追加
[params]
customCSS = ["css/custom.css"]
  2. プロジェクト内の static/css/custom.css というファイルでスタイルを指定する。
    現在の設定はこれ＞ custom.css

ローカルサーバーを起動し、ページをデバッグ表示する

  1. 次のコマンドを実行するとローカルサーバーが起動する。 
    hugo server -D
    ここで -D オプションは、下書き(draft=true)も含めて表示する。
  2. 起動メッセージ内にローカルサーバーの URL が示されるので、ブラウザで開く。 
    :
Web Server is available at http://localhost:1313/hugomemo/
:
    この場合は http://localhost:1313/hugomemo/ にアクセスすればよい。
  3. ブラウザ表示の自動更新について。
    ローカルサーバーを起動した状態で、ソースを書き換えるとブラウザ画面に即座に反映 する。
  4. ここまで設定したテーマと CSS による HTML ページのスクリーンショット。

    ● トップページ


    ● 「投稿のテスト」ページ

完成版の Web サイトデータを作る

  1. 次のコマンドを実行すると public フォルダに、Web サイトのデータが作られる。 
    hugo --cleanDestinationDir
    ここで --cleanDestinationDir オプションは、デバッグ時に作られた不用なファイルをすべて消す指定である。

無料 Web ホスティングで公開してみる

  1. 完成した public フォルダは、そのまま Web サーバーにアップロードするだけで公開できる。 中身は静的 HTML なので、CGI や PHP が使えない無料 Web ホスティング も利用できる。
  2. フォルダ名 public は、baseURL に合わせて変更する。
    今回は baseURL="https://example.net/hugomemo/" だから hugomemo にリネームする。
  3. 実際に FC2無料ホームページ にアップロードしてみた。
    ＞ https://ydat.web.fc2.com/hugomemo/
    あれもう FC2 で良いんじゃない？ とも思ったが、FC2 は3か月放置で広告が出るからね……。

GitHub Pages で公開する

  1. GitHub Page でも同様に、public を hugomemo にリネームして push するだけである。
    前回の記事 で作成した GitHub Pages を確認しておく。
    ＞ https://github.com/yuimax/yuimax.github.io/
  2. まずローカルで、Hugo の public から GitHub Pages の hugomemo にリンクを張る。 
    mklink /j C:\usr\repo\yuimax.github.io\hugomemo C:\usr\hugo\hugomemo\public
    ちなみに mklink /j dst src は、src から dst にリンクを張るコマンド。 これで作られるリンクを「ジャンクション」と呼ぶ。フォルダ専用で、ファイルのリンクは作れない。
  3. このローカルリポジトリを GitHub に push する。
    前回記事で作ったスクリプト deploy.ps1 を利用すると便利。 
    pwsh deploy.ps1
  4. GitHub 側のリポジトリに hugomemo フォルダが追加された。
    ＞ https://github.com/yuimax/yuimax.github.io/
  5. GitHub Pages で Web サイトとして表示されることの確認。
    ＞ https://doc.yuimax.org/hugomemo/

2. GitHub Pages の作り方

GitHub Pages はいわゆる無料ホームページサービスである。 ただし CGI や PHP などサーバーサイドプログラミング環境は使えず、 静的 HTML と JavaScript だけで構築する必要がある。

GutHub Pages の作成方法

  1. GitHub に「ユーザー名.github.io」というリポジトリを作ると自動的に GitHub Pages になる。 ユーザー名が yuimax なら、リポジトリ名は yuimax.github.io である。
  2. リポジトリの作成手順は他の git プロジェクトと同じである。
    まずローカルに yuimax.github.io フォルダを作り、そこに移動する。 
    mkdir yuimax.github.io
cd yuimax.github.io
  3. フォルダに .gitignore を作っておく。下記は当サイトの実例。 
    .*
_*
    .env 等をうっかり公開しないよう、ピリオドネームはデフォルトで管理対象から除外する。
  4. README.md も作っておく。当サイトの実例。 
    # yuimax.github.io
* https://yuimax.github.io
  5. ここが Web サイトのルートになるので index.html も作っておく。当サイトの実例。 
    <!DOCTYPE html>
<html lang="ja">
<head><meta charset="utf-8"></head>
<body><p>ここをキャンプ地とする</p></body>
</html>
  6. フォルダをローカルリポジトリ化し、GitHub に push する。 
    git init
git add .
git commit -m "initial commit"
gh repo create --source=. --public --push
  7. GitHub のリポジトリを確認する。
    ＞ https://github.com/yuimax/yuimax.github.io
  8. しばらく待つと https://リポジトリ名/ でブラウザからアクセス可能になる。
    ＞ https://yuimax.github.io/

独自ドメインのサブドメインでアクセスする

自分の管理するドメインを GitHub Pages に割り当てることができる。 ルートドメインの割り当ても可能だが、ここではサブドメインを使う方法を書く。 参考＞ GitHub Pages: サブドメインを設定する

1. GitHub の使い方

Windows で GitHub を利用する手順。

関連ツールのインストール

  1. Windows 用の git コマンド を入れる。
    Git for Windows がおすすめ。 ←公式のインストーラーをダウンロードして実行する。
    インストールできたら動作確認する。 
    git --version
  2. GitHub CLI (gh コマンド) もあったほうがいい。
    winget を使うと簡単にインストールできる。 
    winget install --id GitHub.cli --source winget
    動作確認する。 
    gh --version

GitHub にアカウントを作る

  1. 公式入口 (https://github.com/) から Sign up を実行する。
  2. ユーザー名 yuimax で登録完了＞ https://github.com/yuimax
  3. 次の段階で必要になるので、ユーザー名 と メールアドレス を覚えておく。

git コマンドの認証設定 (SSH)

  1. ローカル PC に、ユーザー名とメールアドレスを登録する。 
    git config --global user.name "GitHubのユーザー名"
git config --global user.email "GitHubに登録したメールアドレス"
  2. ローカル PC に、SSH 暗号鍵ペアを作成する。 
    ssh-keygen -t ed25519 -C "GitHubに登録したメールアドレス"
    質問の回答はすべてデフォルト（Enterキーのみ）でよい。
  3. フォルダ %USERPROFILE%/.ssh に公開鍵ファイル id_ed25519.pub が作られているので、
    ssh-ed25519 AAAAC3... から始まる行全体をコピーする。
  4. ブラウザで GitHub にログインし、https://github.com/settings/ を開く。
    左のメニューバーで、[SSH and GPG keys] を選択する。
    [New SSH Key] をクリックする。
    Title に任意の識別名を入力し、Key に公開鍵を貼り付けて [Add SSH key] を押す。
  5. 接続テストする。 
    ssh -T git@github.com
    初回接続時に確認を求められたら yes と入力する。

gh コマンドの認証設定

  1. 前項で SSH 暗号鍵は作成済みとする。
  2. gh コマンドで GitHub にログインする。 
    gh auth login
  3. 質問に対し、以下のように回答する。
    What account do you want to log into?
    → GitHub.com
    What is your preferred protocol for Git operations on this host?
    → SSH
    Upload your SSH public key to your GitHub account?
    → Skip
    Generate a new SSH key to add to your GitHub account?
    → No
    How would you like to authenticate GitHub CLI?
    → Login with a web browser
  4. 8文字のワンタイムコードが発行され、コンソールに表示される。
    Enter キーを押すとブラウザが開くのでワンタイムコードを入力する。
    ブラウザの確認ボタンを押して、登録完了。
  5. 動作確認する。 
    gh auth status
    ログイン状態やアカウント情報が表示されれば設定完了。

リポジトリの作り方

  1. まずローカル PC にプロジェクトのフォルダを作り、そこに移動する。
    ここでは myproject という名前にする。 
    mkdir myproject
cd myproject
    以後このフォルダの中で作業を進める。
  2. .gitignore ファイルを作成し、git 管理から除外したいファイルを指定する。
    うちでは下線2個 __ またはピリオド . で始まる名前を管理から外している。
    管理対象としたいものは個別に !名前 として除外を解除（つまり許可）する。 
    # .gitignore の設定例
__*         # 下線2個で始まる名前を管理対象から除外する
.*          # ピリオドで始まる名前を管理対象から除外する
!.github/   # ただし .github/ は管理対象とする
  3. README.md も作成する。GitHub でリポジトリのトップに表示される。 
    # myproject
GitHub の使い方の練習場
  4. Windows の改行コードに関する警告を抑制する。 
    git config --global core.safecrlf false
    git のデフォルト設定では Windows の改行コード CR+LF を LF に変換して GitHub に上げる。 このとき Windows 側に LF が混在していると警告が出るらしいが、無視しても問題ない。
  5. git init でリポジトリを初期化する。 
    git init
    するとサブフォルダ .git に設定が保存される。 .git は通常は見えないが、dir /a で見える。 以後このフォルダは git リポジトリ として扱われる。
  6. 現在の状態をリポジトリに記録する。 
    git add .
git commit -m "initlal commit"
    現状記録が add → commit の2段階処理なのは、 add の間違いを取り消せるようにしたらしいが、 うちでは add 即 commit なので2段階に分ける意味はなかったりする。
  7. ローカルリポジトリを元に、GitHub に新しいリポジトリを作る。
    これは gh コマンド を利用すると簡単である。 
    gh repo create --source=. --public --push
    すでに GitHub 側にリポジトリが存在するとエラーになる。
  8. GitHub にリポジトリが作られたらブラウザで確認する。
    この時点のリポジトリ＞ https://github.com/yuimax/myproject/tree/2e8...

プロジェクトの更新をリポジトリで管理する

  1. ファイルを編集・追加・削除したらリポジトリを更新する。
    まずローカルリポジトリに対し add + commit を実行し、現状を記録する。 
    git add .
git commit -m "ファイルを追加したよ"
    最近は AI でメッセージを生成したりするが、ここでは自力でメッセージを書く。
  2. ローカルリポジトリを GitHub に push する。 
    git push origin main
    これで GitHub 側のリポジトリも更新される。
    この時点のリポジトリ＞ https://github.com/yuimax/myproject/tree/7df...

過去の状況を見直す

  1. git では過去に commit した時点の状況を、いつでも見返すことができる。
    過去を見るのはローカルでも可能だが、GitHub の機能を利用すると便利である。
  2. それには GitHub で commit の履歴を表示する。
    ＞ https://github.com/yuimax/myproject/commits/
    そして 見たい commit の右端の <> をクリックする と、当時のファイル一覧を表示する。
  3. なお、ローカルで commit の履歴を見るには、git log コマンドを利用する。
    --oneline オプションを付けると、1回の commit が1行に表示されるので見やすい。 
    git log --oneline
  4. 過去のファイルをローカルで確認したい場合は、git show コマンドを利用する。
    まず git log --oneline で、左端のコミットハッシュ値を調べる。
    たとえばハッシュ値が 2e8392b なら、 git show 2e8392b:ファイルパス を実行すると、その時点のファイルの内容が出力される。 
    git show 2e8e92b:./README.md
    出力結果をリダイレクトしてファイルに書き込めるので、バイナリ画像データなども取り出せる。

GitHub のリポジトリを削除する

  1. ブラウザから GitHub リポジトリを削除する方法。
    ブラウザで目的のリポジトリを開く。
    上部メニューバーから [Settings] を開く。
    ページ最下部の [Delete this repository] ボタンを押す。
    何回か確認ダイアログが出るので、全部正しく答えると削除完了。
  2. ローカルで gh コマンド を使っても削除できるらしい。やったことはないが手順だけ示す。
    まず gh コマンドに削除権限を付与する。 
    gh auth refresh -s delete_repo
    これで次のコマンドにより、GitHub 側のリポジトリを削除できる。 
    gh repo delete yuimax/myproject

ローカルのリポジトリ情報を削除する

  1. プロジェクトのファイルを消さずにリポジトリ情報だけリセットしたいことがある。
    .git フォルダをまるごと削除すれば、リポジトリ情報がすべて消える。 
    rmdir /s /q .git
